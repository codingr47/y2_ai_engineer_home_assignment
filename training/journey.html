01 / Define success

The whole answer has to be right.

A search parser must identify a domain, detect the requested fields, find their values, and normalize everything into {category, params}. Getting the city right while missing the price cap still makes the full answer wrong.

Hebrew query→Domain + fields→Spans + values→Normalized JSON

For example, דירת 4 חדרים עד 2 מיליון asks for four rooms and a maximum price. The bound belongs to the price field; it must not change the room count.

Three different measurements

Field-set exact: all requested fields detected, with no extras.

JSON exact: domain, fields, and normalized values all correct.

Routing: coverage is the share answered locally; accepted accuracy measures only those answers.

Keep the data roles separate

Train fits models. Development chooses configurations. Calibration sets thresholds; an audit checks them.

Test checks a frozen configuration. The tagger uses 17,272 train rows, 3,436 validation rows and the same 2,181 test rows used for the earlier comparison.

Reading rule: compare within a labeled chart or table. A field-detection score, a search-only development score, and an all-query test JSON score are different measurements.

02 / Frozen Fusion · experiments 1–3

Semantics needed surface detail.

Could a frozen sentence encoder detect the complete filter set? E5 provided a baseline, but lexical identity—brands, amenities, morphology—was being blurred.

Word and character TF-IDF features lifted test slot exact-set accuracy by 14.2 points over slot-trained E5. Combining both representations added another 3.4 points. Family-level bootstrap intervals excluded zero: +11.9 to +16.5 points for TF-IDF over E5, and +1.8 to +5.0 for fusion over TF-IDF.

Keep the complementary representations. TF-IDF preserves surface cues; E5 helps recover semantic paraphrases, long queries, and spelled-out numeric concepts. TF-IDF alone remained the lower-latency option, about six times faster per query in the recorded benchmark.

Label correction and the full comparison

Seven point/range twin pairs reduced 77 raw fields to 70 detection slots. Schema v2 then folded range names into point fields and canonicalized the vehicle-year label, leaving 69 fields. This removed a naming inconsistency; bounds remain in the values. The original-slot and v2 results below are separate evaluations.

03 / Frozen Fusion · experiments 4–7

Fix the bottleneck, then recognize the plateau.

Once fields were known, extraction was relatively strong. The larger loss came from fields the classifier never selected.

96.9% of supplied-field values correct

The first extraction evaluation supplied gold fields for 1,019 development queries. Value accuracy was 96.9%; 92.2% of searches had every value correct.

The full pipeline achieved 81.1% JSON exact. Extraction could remove false-positive fields as well as introduce value errors, so JSON exact did not simply equal field accuracy minus extraction errors.

Targeted fixes helped

Field-local operators, Hebrew number reading, coherent ranges, negation, and safer fuzzy matching improved extraction. Cities such as באר שבע stopped producing accidental numbers.

With the later fixes, supplied-field value accuracy reached 97.3% on development.

Rejected: random typo augmentation. One or two noisy copies per training row gave at most about one point on routing typo queries, offset by losses elsewhere. Real failures involved new phrasings and structured spelling errors.

04 / Fine-Tuned Tagger · experiment 1

Learn the fields and their spans together.

The next phase fine-tuned DictaBERT-base end to end for domain, field presence, BIO spans, operators, and implied values. Deterministic normalization stayed in the pipeline.

The final configuration used a three-seed ensemble, an encoder learning rate of 5e-5, eight epochs, improved number normalization, and an extractor fallback for non-numeric fields with presence probability ≥ 0.5. Runtime query cleanup added a further eight net correct test answers: ten fixed and two broken.

Adopted

Better decoding, modest ensembling

Normalizer fixes raised mean dev JSON from 89.3% to 90.2%. The fallback brought it to 90.7%. The final ensemble reached 91.2% dev and 84.8% test before runtime cleanup.

Rejected

More capacity was not the answer

The categorical value head reduced accuracy. DictaBERT-large reached 89.5% at best, below the comparable 90.4% base model, at about 1.8× the epoch time.

05 / Fine-Tuned Tagger · experiments 2–3

Better answers still need a calibrated exit.

Frozen Fusion became more valuable as a second opinion than as a replacement answer. Agreement between the two systems helped a learned gate decide which queries to answer locally.

E1/E2 rows use the pre-registered 95% target. E2 is calibrated on validation; E3 uses a separate routing fit/selection/audit protocol. Lower bounds shown for the routing audit are computed over accepted units. These rows describe different evaluation sets, not one continuous improvement curve.

A target is not a guarantee. The E2 gate answers 84.5% of test queries locally, but its accepted accuracy is 92.9%, below the 95% target. The E3 routing-calibrated gate clears the 95% audit lower bound, at just 39.1% coverage. That certification applies to this audit protocol and population; the gold subset alone is too small to support the same claim.

Rejected

Arbitrating disputed fields

A per-field model tried choosing between tagger and fusion outputs. Its apparent dev gain failed on val_calib: 90.5% → 90.4%, with five rows fixed and seven broken.

Keep fusion as a gate signal; do not use that arbiter to rewrite answers.

Human check

A blind audit of 120 labels

The user reviewed 80 bulk-approved silver labels and 40 synthetic-v2 labels. One label was explicitly wrong; the validation-weighted error estimate was 0.7%.

Including missing-field notes gives roughly 2–3%. This small audit does not establish an exact label-quality ceiling or prove labels are never a bottleneck.

Routing caveats, historical costs, and data-role provenance

The recorded E2 cost scenario assumes about 33 million monthly searches and roughly $0.10 per 1,000 LLM calls: approximately $505/month in fallback calls versus $3,250 for LLM-only. These are historical rounded assumptions and exclude local inference infrastructure.

A routed system’s total accuracy requires measuring the fallback on the rejected queries. Applying an LLM’s average accuracy to that harder subset gives an estimate, not an observed result.

Earlier Frozen Fusion experiment 5 used routing fit/selection rows as development data and explicitly required a new calibration batch afterward. The later tagger experiment 3 reused the recorded routing partition and reports a unit-based audit. Read its certification in that documented context; do not present the entire routing dataset as untouched across the whole research history.

The hybrid-fuel → vehicle-type product rule remains off by default: enabling it conflicts with the current labels. Its adoption requires changing the labeling convention too.

06 / Decisions to carry forward

Accuracy improved. Trust remains conditional.

Keep

  • Fine-tuned Hebrew tagging with deterministic normalization and a field-local fallback.
  • Complementary models as signals for correctness.
  • Family-aware splits, explicit metric definitions, and independent threshold audits.

Do next

  • Collect more realistic hard queries, especially typos and real estate; prioritize gold-like coverage.
  • Follow the documented fresh-data generation plan before claiming stronger routing guarantees.
  • Measure fallback outputs on actual rejected queries and total inference cost.

The main result

Full JSON test accuracy rose from 75.4% with Frozen Fusion to 85.1% with the cleaned tagger. A second model improved routing coverage, while independent checks exposed the gap between a useful operating point and a certified accuracy target.
